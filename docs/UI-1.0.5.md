# Petrichor Android 1.0.5 · 缓存与播放手势

本轮处理上下翻页、媒体进度条、启动和切页等待数据的问题。保持既有紧凑尺寸、动态取色、贴底播放栏和点击封面切换歌词。

## 数据与启动

- 把本地文件库、Cookie 和加密保存的最近账号资料恢复，与联网验证账号拆开。页面不再等待账号验证请求完成才能加载。
- 新增响应缓存：内存最多 128 项；应用私有目录最多 128 个文件、24 MiB。只缓存明确允许的读取接口，按账号、接口及完整查询参数隔离。播放地址、密码、验证码、二维码和登录响应不进入页面缓存。
- 常用列表、歌单及歌曲详情、歌手／专辑、搜索、播客与评论可以跨进程恢复。普通内容有效期 5 分钟，评论 1 分钟；7 天内的过期内容先显示，再异步更新。后台刷新失败保留已有内容；超过 7 天重新请求。
- 相同请求合并，离开一个页面只取消该页面的等待，不中断其他页面或预加载共用的请求。返回仍有效的现有页面保留视图；相关缓存变更后再更新。与页面无关的后台缓存更新不重建其列表。
- 主页先发起自己的请求，随后依次预取热门播客、排行榜、歌单广场；有账号时预取歌单与日推。
- 首次无数据时使用静态骨架占位。列表构建等待入场动画结束，避免转场与列表填充争用主线程。占位不运行持续闪动动画。
- 账号资料只用于本地展示恢复，联网验证仍会执行；服务端继续决定账号、播放及修改权限。退出登录清除页面缓存。歌单、喜欢、收藏、订阅和评论修改成功后使缓存失效，避免读回修改前的结果。
- 安全存储中的 Cookie 只在实际变化时写入，退出后重置去重状态，确保再次登录能重新保存。

## 手势与进度条

- 播放页改用 Android 原生触摸分发、方向判定和速度追踪。可从封面以外区域上滑进入功能区，在功能内容处下滑返回；歌词和功能列表先消费自己的滚动，到边界后才交给翻页。横向拖动进度条不触发上下翻页。
- 跟手阶段在页面范围内按手指移动，到边缘才有阻力。松手按距离和速度吸附，小幅慢拖回弹；动画可被后续手势中断。系统关闭动画时直接完成切换。
- 参考 [Material Android 官方滑块文档](https://github.com/material-components/material-components-android/blob/master/docs/components/Slider.md)中的把手与轨道分离、6 dp 间隔、4 × 44 dp 把手及末端停止点，保留 48 dp 高的交互区域。
- 音乐媒体波浪参考 [Android SystemUI 的 SquigglyProgress](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android13-release/packages/SystemUI/src/com/android/systemui/media/SquigglyProgress.kt)：播放时相位移动，暂停时振幅逐渐收回，波浪在末端过渡为平直。这里结合应用的 Material 颜色及分离把手，使用适合媒体栏的细轨道，并非套用整套 Expressive 粗轨道样式。
- 继续使用原生 SeekBar 的触摸、键盘及无障碍行为，绘制依据原生把手的实际位置。波浪只使该原生控件重绘，不在每帧更新 MAUI 布局；暂停后停止持续绘制。
