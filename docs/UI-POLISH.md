# 1.0.3 界面与运行检查

以安卓模拟器的实际渲染为准。此轮修复保留现有 MD3 稿件与动态配色，使用 Android 原生编辑控件替换登录、搜索及新建歌单中的输入框。截图和原始日志位于 `artifacts/polish/`。

## 当前版本中确认的问题与修改

| 步骤 | 原生界面发现 | 实现修改 |
| --- | --- | --- |
| 1 首页 | 首次进入要等待推荐与播客请求结束才出现正文，等待期间大块空白 | 首屏结构先显示，推荐与播客分别填充；失败保留可重试入口 |
| 2 我的 | 返回访客页时反复创建相同内容 | 缓存访客布局，账号状态变化仍重新加载 |
| 3 登录 | 文字贴上沿，浮动标签被裁切；连续输入偶发字符乱序 | 固定输入高度并居中；为标签预留完整空间；直接使用原生 AppCompatEditText 管理编辑缓冲、光标、选区和输入法 |
| 4 搜索与曲目列表 | 每条结果单独刷新；普通行重复测量；加载更多长期占用底部空间 | 批量更新结果，等高行复用测量；移除普通行额外圆角容器；接近末尾再显示分页操作 |
| 5 歌单与菜单 | 返回歌单时重新请求并重建；全选重复计算和刷新计数；折叠详情头后全选/完成滚出屏幕 | 账号不变且没有修改时保留列表；全选只更新一次计数；选择工具栏固定在列表上方，单首操作继续绑定歌曲身份 |
| 6 歌单广场/排行榜 | 分页将整份封面网格放进列表头部，每次追加都重新构造所有卡片 | 改用可回收的两列 CollectionView 单元格，追加数据不重建全部封面 |
| 7 外观与播放栏 | 相同主题重复写入资源；播放进度修改布局宽度；部分点击区域偏小 | 颜色相同不重刷；进度仅重绘；播放栏按钮与验证码按钮使用48dp点击区域 |
| 8 校验提示 | 安卓运行时参数名后缀混入错误文案 | 按当前运行时实际后缀移除技术参数文字，登录和歌单弹层共用处理 |

实际截图还发现带图标的「播放全部」按钮文字被裁切。字体图标加载后，安卓文字布局仍沿用旧宽度：实测可用165像素、缓存249像素。现预留图标宽度，并仅在缓存与可用宽度不一致时，按最终尺寸重新测量原生按钮。该Handler只应用于图标与文字组合按钮。相关框架异步图标行为可对照 [MAUI Android ButtonHandler](https://github.com/dotnet/maui/blob/10.0.110/src/Core/src/Handlers/Button/ButtonHandler.Android.cs)。歌单网格补回播放量标记，标题允许随字体尺寸扩展。

连续系统返回时曾复现无崩溃日志的空白页。返回、进入页面与切换底部页签共用导航互斥，系统返回和登录完成后的返回也经过同一入口，避免两个返回动画重叠。`scripts/Verify-AndroidNavigation.py`重复进入公开歌单并快速返回，结果单独保留。

## 性能方法

旧版1.0.2源码保存于 `source-before.zip`，仅修改包名生成独立的 `app.petrichor.baseline`，以便与新版本同机对照。旧版对照包不是交付版本。

- `scripts/Measure-AndroidScroll.py`：相同30条 Coldplay 单曲结果，4次向上、4次向下，450ms滑动，记录 Android gfxinfo 原始帧数据。
- `scripts/Measure-AndroidStartup.py`：两版交替执行3次进程冷启动，记录 `am start -W TotalTime`。它是首帧时间，不代表远程内容加载完成时间。
- 使用 Android 15 / API35 / x86_64 模拟器，1080×2400、4核、3GB内存、NVIDIA GTX1650主机GPU加速。数据仅用于同环境对比，不能代表实体手机帧率；原始数据与设备状态一并保留。
- 早期SwiftShader软件渲染记录与电脑休眠后的异常波动不用于新版性能结论；对照数据在重启模拟器、恢复GPU加速且构建结束后重新采集。每版列表先预热一轮，再记录相同8次滑动。

Release 使用预编译和SDK部分裁剪，保留共享业务模型成员。首个预编译中间包曾发生依赖GUID不一致，已调整配置并重新生成。此类问题不能仅凭构建成功判断，需要安装启动验证。相关机制见 [Android构建属性](https://learn.microsoft.com/en-us/dotnet/android/building-apps/build-properties) 与 [上游AOT/裁剪问题记录](https://github.com/dotnet/android/issues/7178)。

## 最终包检查结果

- Release 1.0.3 / versionCode 4，构建0错误；模拟器安装包与交付APK的SHA256一致。
- 98项业务检查、13项原生输入检查通过。快速系统返回连续3轮通过；97首公开歌单全选、滚动时工具栏保持可见和退出恢复通过；也检查过199首场景，早期UI层级记录另存。
- 同场景预热后的8次搜索列表滑动：旧版2/256帧被Android标记为卡顿，新版1/264帧；两版p95均18ms。该场景差异很小，不能据此宣称所有卡顿已解决。
- 最终包3次进程冷启动首帧为1961、1273、1164ms；对照包为3642、3432、1638ms。样本波动明显，只保留原始数据作为参考，不推断真机提升幅度。
- 最终运行记录未发现Java致命异常、原生致命信号或ANR。完整数据、20张截图与修复前后对照见 `artifacts/polish/index.html` 和 `report.json`。

## 边界

不使用真实账号密码、不发送短信、不执行账号歌单或评论写入。本轮原生检查覆盖访客页面、公开搜索、所属播客跳转、长按、多选与主题；账号功能保留已有业务检查，不能算作真实账号验收。截图不能证明全部无障碍要求，实体ARM64手机上的流畅度、持续播放和厂商电池策略仍需真机检查。
